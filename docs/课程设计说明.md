# 民宿预订与房态管理系统课程设计说明

## 一、选题

- 选题：AU. 16B 民宿预订与房态管理
- 业务范围：房源、房态、订单、评价
- 技术方向：Java EE / Spring Boot Web 应用

## 二、需求分析

民宿经营后台需要解决以下实际问题：

1. 门店和房型信息分散，缺少统一档案。
2. 不同日期的订单会占用库存，手工核对容易超卖。
3. 订单需要经过确认、入住、完成或取消等明确状态。
4. 住客评价需要被记录、回复和管理。
5. 经营者需要快速了解入住率、到店客人和营收。

## 三、功能设计

| 模块 | 主要功能 |
| --- | --- |
| 登录 | 管理员 Session 登录与拦截 |
| 经营概览 | 房量、入住率、到店、营收、未来七天趋势 |
| 门店房源 | 门店查询、新增、编辑、详情 |
| 房态管理 | 房型档案、库存、价格、保洁与维护状态 |
| 订单中心 | 新建预订、日期校验、状态流转、取消释放库存 |
| 住客评价 | 评分、评价、回复、公开/隐藏 |
| 数据接口 | 健康检查、看板 JSON |

## 四、系统架构

系统采用经典分层结构：

```text
Browser
   ↓
Spring MVC Controller
   ↓
Service 业务层
   ↓
Spring Data JPA Repository
   ↓
H2 / MySQL
```

前端使用 Thymeleaf 服务端渲染，避免额外部署前端工程。静态 CSS、JavaScript、图标和图片均存放在项目内。

## 五、关键业务规则

### 1. 日期与库存

- 入住日期不能早于当天。
- 离店日期必须晚于入住日期。
- 单次预订最多 30 晚。
- 预订间数和入住人数必须为正数。
- 同一房型的待确认、已确认和已入住订单按日期重叠累加库存。

### 2. 房态

- 可预订：允许创建新订单。
- 保洁中：暂停新房预订。
- 维护中：暂停新房预订。

### 3. 订单状态机

```text
待确认 → 已确认 → 已入住 → 已完成
   ↘         ↘
   已取消     已取消
```

已完成和已取消是终态，不允许继续执行其他状态操作。

### 4. 评价

- 只有已完成订单可以录入评价。
- 同一订单只能评价一次。
- 隐藏评价不参与公开平均评分。

| id | BIGINT | 主键 |

| address | VARCHAR(160) | 地址 |

## 七、测试说明

项目包含 12 项自动化测试，覆盖：

- 登录页正常渲染
- 未登录访问后台时跳转到登录页
- 经营概览、门店、房态、订单、评价、预订页面渲染
- 订单详情、房型编辑、门店编辑页面渲染
- 演示数据初始化
- 下单金额与库存占用
- 待确认到已完成的订单状态流转

运行命令：

```bash
mvn test
```
